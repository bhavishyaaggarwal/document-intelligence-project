The financial files cover 2017 through 2026.

## PDF characteristics

The supplied financial PDFs are not uniform from an extraction perspective.

- Balance Sheet: all 10 are one-page PDFs; most are image-only and require OCR.
- Profit & Loss: all 10 are one-page PDFs; most are image-only and require OCR.
- Cash Flow: 2017–2020 and 2024–2026 contain two pages; 2021–2023 contain one page. Most are image-only.
- The 2022 Cash Flow PDF exposes selectable text in the supplied file, so the native text path can be exercised.
- Older statements use thousands (`in '000`) while newer statements use crore. The parser therefore preserves the document's unit/currency context rather than applying a hardcoded conversion.

The statement layouts are visually related but change typography, branding, column highlighting and table density across years. Comparative periods are common.

## Invoice characteristics

The 20 JPG invoices include:

- thermal/retail receipt layouts
- photographed and rotated paper receipts
- low-contrast receipts
- Malaysian GST-era receipts using RM/MYR and tax-inclusive totals
- clean North American business invoices with seller/client blocks
- invoices containing tax IDs, due dates, shipping/handling, notes and payment terms
- multi-row line-item tables

The rotated photograph `20251118_000612.jpg` is particularly difficult for OCR. It is useful as a negative/robustness case because a deterministic OCR fallback cannot guarantee complete recovery from severe image degradation.

## Extraction implications

1. Do not rely on one fixed invoice template.
2. Use page images for difficult scans, not only extracted PDF text.
3. Preserve comparative statement columns.
4. Treat parentheses as negative values.
5. Do not assume tax is separate from the displayed total.
6. Use null/NOT_APPLICABLE when evidence is missing.
7. Keep financial validation independent of filename and dataset-specific expected answers.

## Representative local processing

The repository's `sample_outputs/` directory contains outputs generated by running the actual local OCR/fallback pipeline against supplied files. They are explicitly marked by `processing_metadata.extraction_method`. They are not manually authored ground-truth answers.

The high-accuracy extraction path is the optional multimodal LLM path, which uses OCR text plus page images. It requires an API key and should be used for the final deployed assessment demo.
